# 不懂 Kotlin，也可以先安装使用

APK 就是安卓手机的安装文件；Kotlin 是开发它使用的语言。**使用软件不需要学习 Kotlin，也不用先安装 Android Studio。**

## 一、把 APK 装到手机

项目位于 `/data/httpd/smslistener`。交付安装包位于该目录下的 `artifacts/smslistener-0.2.0-debug.apk`。

1. 在电脑上找到这个 APK 文件。若项目在服务器上，用你平时的文件传输工具把它下载到电脑；若是在 WSL 中，在 Windows 文件资源管理器地址栏输入 `\\wsl.localhost`，进入对应 Linux 系统，再进入 `data → httpd → smslistener → artifacts`。
2. 用 USB 数据线或你常用的文件传输方式，把 APK 传到 K90 手机的“下载”文件夹。
3. 在手机“文件管理”中找到并点击 APK，按系统提示安装。
4. 如果提示不允许此来源安装，按提示为当前文件管理器允许“安装未知应用”，然后返回安装。只授权你正在使用的安装来源即可。
5. 安装完成后打开 **短信哨兵**。

这是供你自己测试的安装包，没有上架商店。它可以与 SmsForwarder 同时安装。为了清楚判断测试结果，建议先暂停其他应用里对同一短信的报警规则。

如果已经安装 0.1.0，直接安装新版覆盖更新即可，同一签名下会保留已保存的规则。不要先卸载旧版。

## 二、授权并设置后台运行

点击底部“工具”，在“运行准备”区域：

1. 分别点击“接收短信”和“显示通知”，完成授权。
2. 点击“后台运行”，按系统提示允许。
3. 点击“澎湃 OS 自启动”，在澎湃 OS 里寻找本应用的“自启动/后台自启动”，允许；将省电策略设为“无限制”。不同系统版本名称可能略有区别。
4. 确认系统允许在锁屏上展示短信哨兵的通知，便于锁屏时停止报警。
5. 在系统“声音与触感/音量”中将**闹钟音量**调到合适大小。媒体音量和闹钟音量不是同一个设置。

首次验证建议关闭勿扰模式。以后可以专门测试你日常使用的勿扰设置是否允许闹钟响铃和振动。

不需要默认短信应用、无障碍、悬浮窗或 root 权限。没有必要把系统中所有权限都打开。

## 三、先测试振动和声音

先不用保存关键词，直接在“概览”点击测试卡片，或打开底部“工具”页。

| 操作 | 应当观察到的结果 |
| --- | --- |
| 点击“振动测试” | 振动 0.8 秒、间隔 0.4 秒重复，约 5 秒后停止 |
| 点击“响铃测试” | 双音铃声重复，约 5 秒后停止 |
| 测试进行中点击顶部红色提示中的“停止报警” | 当次报警结束 |

每个测试结束后再进行下一个。测试时长从报警服务启动计时，并不表示手机已经实际振动了完整 5 秒。

如果这里仍然完全不振动，点击“诊断与运行日志”→“复制诊断”，把结果发给我。此时应先排查振动，不必反复更换短信关键词。日志“已提交闹钟用途的循环振动请求”只表示 Android 接受了 API 调用，是否实际振动仍需你观察。

## 四、设置你的第一条规则

例如你希望收到包含“告警”的短信就持续报警：

1. 点击底部“规则”，在关键词框里填写 `告警`。
2. 选择“任意一个”匹配模式。
3. 排除词暂时留空。
4. 开启“循环响铃”和“循环振动”开关。
5. 在“什么时候停止”选择 **手动**，持续提醒直到手动停止。也可以选 30 秒、60 秒，或选“自定义”输入 1～3600 秒；自定义输入 0 同样表示手动停止。
6. 点击底部“保存规则”，会回到概览。再点“开启监听”；若出现“完成必要授权”，按提示补齐权限后回到概览开启。保存规则本身不会自动开启监听。

以后可以每行写一个关键词，例如：

```text
告警
故障
服务器宕机
```

默认命中其中一个就报警。如果选择“同时包含全部”，同一条短信必须三个词都有才报警。

如果不希望恢复通知也报警，在排除词中填写 `已恢复`。这样“故障告警”会报警，“故障告警已恢复”不会报警。

号码不需要填写，陌生号码也参与匹配。关键词按字面包含判断，不是智能语义判断。

## 五、用真正的短信验证

1. 使用**另一部手机**向 K90 的手机号发送普通 SMS 短信：`测试：设备告警，请处理`。
2. K90 应开始响铃和循环振动，通知栏出现“停止报警”按钮。
3. 点通知里的“停止报警”，或打开短信哨兵点顶部红色提示中的“停止报警”。
4. 再发 `这是一条普通测试短信`，应该不报警。
5. 返回桌面后重复一次，再锁屏等待几分钟后重复一次。

请确认发送的是运营商普通短信。微信消息、RCS/5G 消息不会触发本项目的短信接收器。

工具页的“短信匹配检查”只是帮你检查文字是否匹配，**不会响铃，也不能证明手机收到短信时的后台流程正常**。

## 六、日常使用

- 确认概览显示监听“已开启”后，可以返回桌面。待机时应用不需要一直显示在前台。
- 停止一次报警不会关闭短信监听，下次匹配短信还会触发。
- 想彻底暂停，在概览点击“暂停监听”；这也会停止当前报警。
- 修改关键词、声音或时长后，记得在规则页点击“保存规则”。
- 报警中又收到匹配短信会合并，点一次停止即可；如果设置了自动停止时间，不会被新短信延长。
- 不要用系统“强行停止”作为日常退出方法；强行停止后必须重新打开应用。
- 手机重启后先解锁一次，再验证短信接收。

## 七、遇到问题怎么区分

| 现象 | 先做什么 |
| --- | --- |
| 点击 5 秒测试也完全不振动 | 复制诊断和日志，确认“振动器存在”，检查系统振动、勿扰设置 |
| 有振动但没有声音 | 检查系统闹钟音量，先单独测试响铃 |
| 手动测试正常，真实短信不报警 | 看日志有无“收到短信”；没有则查短信权限、自启动、是否实际 SMS |
| 有“收到短信”，但显示未命中 | 检查已保存关键词、“同时包含全部”选项和排除词 |
| 日志显示后台启动被阻止 | 检查电池优化、澎湃 OS 自启动/后台运行设置 |
| 前台能用，锁屏不能用 | 保留失败时日志，重点验证后台和省电策略 |
| 安装提示与现有应用签名冲突 | 先确认是不是不同电脑生成的 APK；直接卸载会丢失配置，不要急着卸载 |

更完整的测试清单见 [DEVICE_TESTS.md](DEVICE_TESTS.md)。当前还没有 K90 真机测试结果，不能保证一定绕过澎湃 OS 的所有限制。

## 八、以后你想自己改代码时

这部分现在可以跳过。首次学习建议先改一个按钮文字，确认能重新打包，再改功能。

1. 在电脑安装 [Android Studio 官方版](https://developer.android.com/studio)。完成首次启动的 SDK 安装向导。
2. 如果项目在服务器上，把源码目录复制到电脑本地；Windows 下不要把 Linux 的 `local.properties` SDK 路径照搬过去。
3. 在 Android Studio 选择 **Open**，打开包含 `settings.gradle.kts` 的 `smslistener` 根目录。
4. 等待 Gradle 同步。按提示安装 Android SDK Platform 36 和 Build Tools 35.0.0。项目 Gradle 配置请选择 JDK 21，以运行 Android 16 模拟框架测试。
5. 界面文字主要在 `app/src/main/java/io/github/smssentinel/ui/MainActivity.kt`。例如修改首页副标题“让重要的消息，被及时听见。”。
6. 在 IDE 终端执行 `./gradlew testDebugUnitTest lintDebug assembleDebug`；Windows PowerShell 执行 `./gradlew.bat testDebugUnitTest lintDebug assembleDebug`。
7. 命令成功后，新安装包在 `app/build/outputs/apk/debug/app-debug.apk`。把它传到手机安装即可。

调试 APK 的签名通常与构建电脑相关。不同电脑生成的调试 APK 可能无法相互覆盖安装。长期维护时，使用 Android Studio 的 **Generate Signed Bundle / APK** 为自己创建正式签名，并保管好密钥和密码，以后一直使用同一密钥打包。

代码阅读顺序：`core/KeywordMatcher.kt`（规则）→ `sms/SmsReceiver.kt`（收到短信）→ `alarm/AlarmService.kt`（执行报警）→ `alarm/AlarmVibration.kt`（调用振动）。
